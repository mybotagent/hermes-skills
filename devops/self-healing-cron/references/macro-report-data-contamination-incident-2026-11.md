# Macro Report Cron — 데이터 오염 사고 기록 (2026-11-05)

> 자기치유(self-healing) 관점의 핵심 교훈:
> **"에러가 난 리포트"보다 "조용히 틀린 리포트"가 훨씬 위험하다.**
> 오류/실패는 self-healing watchdog이 잡지만, 틀린 값은 18:35 파이프라인이 그대로
> 포트폴리오 비중 결정에 씹어 들어간다. 어떤 자가치유 장치도 잡지 못한다.

## 사고 요약

2026-11-05 매크로 리포트 크론에서 KOSPI -5.28% 폭락 리포트를 생성.

**발생한 것**
1. Naver Polling API로 종목 등락률을 수집 → 삼성전자 `+6.88%`(실제 -8.58%)처럼 **부호가 반대**인 값.
2. Polling 값과 뉴스 방향이 충돌 → siseJson으로 재확인하는 과정에서
   정규식 버그로 `rows 0` (6종목 전부).
3. **이를 bypass하고 초안 수치로 `macro_context.json`을 먼저 저장**(양경로, timestamp 일치 확인까지 완료).
4. 이후 siseJson 검증 완료 → 종목 등락률 전부 변경:
   | 종목 | 저장된 값 | 검증값 |
   |:--|--:|--:|
   | 삼성전자 | -8.35% | **-8.58%** |
   | SK하이닉스 | -10.63% | **-10.77%** |
   | 삼성전기 | -14.48% | **-15.01%** |
   | HD현대일렉트릭 | -9.88% | **-10.21%** |
   | 현대차 | +2.61% | **+2.26%** |
   | 에이피알 | +5.51% | **+5.31%** |
5. 유가 서사도 반대: "오늘 유가 8% 급락" → 실제로는 **전일 -8.29%, 오늘 +0.58%**.
6. 뉴스 선별 정리 스크립트가 `TypeError`로 죽어 73건 수집 결과가 선별 단계에서 유실.
7. 도구 호출 한도 도달 → 최종본 미완료, Discord 미전송.

**왜 위험했나**
- 저장 파일은 18:35 LangGraph `pipeline.py`가 읽는 경로. 검증 전 값이 그대로 소비됨.
- 파일은 syntactically 완벽하고 timestamp도 일치 → 어떤 검증도 "정상"으로 봄.
- watchdog의 `status == 'error'` / `last_delivery_error` 체크도 걸리지 않음.

## 확정된 규칙

### R1. 검증 → 작성 → 저장 → 전송 순서는 강제. 순서 역행 금지

```
1. 수집 (개별주 / 지수 / 선물 / 환율 / 뉴스)
2. /tmp/*.json 으로 원자료+파싱 결과 캐시
3. 교차검증 (최소 2개 소스)
4. 검증된 값으로 본문 작성
5. 본문 QA (CJK / 한영혼합 / 수치 재확인)
6. 두 경로 저장 + timestamp assert + cp
7. Discord 전송
```
"일단 저장해 두고 나중에 고치기" → **금지**. 파이프라인이 18:35에 읽는다.

### R2. 수치 소스 우선순위 (2026-11-05 확정)

| 대상 | 1순위 | 금지 |
|:--|:--|:--|
| 한국 개별주 종가·등락률·주간수익률 | Naver `siseJson` | Naver Polling (`cr` 부호 역전 가능) |
| KOSPI / KOSDAQ | Naver `siseJson?symbol=KOSPI` / `KOSDAQ` | Yahoo `^KS11` (429), CNBC HTML |
| 미국 지수·금리 | CNBC XML (`.SPX` `.DJI` `.IXIC` `.SOX` `.VIX` `.DXY` `US10Y` `US30Y` `US2Y`) | Yahoo (429) |
| 선물(WTI·Brent·금) | CNBC HTML embed (`last`/`change_pct`/`last_time`) | CNBC XML (stale pdc) |
| 환율 | `open.er-api.com` / `api.frankfurter.app` | — |
| 종가 방향 확인 | siseJson `previous_day_closing` | Polling `cr` |

### R3. 방향성 서사는 "직전 세션"과 "현재"를 분리

뉴스 헤드라인은 보통 **직전 해외 세션**의 events다. 크론 실행 시각 현재가는 그 반대일 수 있다.
→ 항상 ① 직전 세션 news ② 현재가 + change_pct ③ previous_day_closing 을 따로 확인하고
"전일 -8.29% 급락 → 오늘 +0.58% 반등"처럼 양쪽을 함께 기술.
**한쪽만 단정하면 현재가와 모순되고, 그 모순이 그대로 리포트로 나간다.**

### R4. 마감 판정 같은 "경계값"은 숫자로 확인

삼성전기: 전일 1,119,000 → 하한가 `round(1,119,000*0.85, -1)` = 951,000 → 종가 951,000
= **하한가 마감**. 리포트 임팩트 서술에 "하한가 마감"을 명시해야 함.

### R5. 정리/선별 스크립트는 수집 결과를 잃지 않게

정적 헬퍼 시그니처를 어긋나게 호출(`newest(..., must=...)`)하면 `TypeError`로
**이미 수집한 73건이 통째로 유실**된다. 다수 헬퍼를 정의할 때:
- 시그니처 통일
- 최소 1회 인자 없이 호출해 스모크 테스트
- 수집 결과는 먼저 **파일로 캐시**하고, 선별은 그 파일에서만 읽기

### R6. 본문 QA는 "정정 후"에 다시

CJK(한자) 검사와 한영혼합어 검사(`[가-힣]([A-Za-z]{3,})` + 화이트리스트)를
**정정 수치로 본문을 다시 쓴 뒤** 수행. 정정 과정에서 새 오염이 생김.
수정은 일괄 replace가 아니라 **항목 단위 정상 한국어 재작성**
(예: `投机`→`투기` 일괄 치환 시 `가장 커투기적` 같은 새 결함).

### R7. 자기치유가 잡는 것 vs 못 잡는 것

| 잡음 | watchdog |
|:--|:--|
| 예외 / 타임아웃 / 404 / 429 / 빈 응답 | ✅ 잡음 |
| 조용히 틀린 값 (부호 역전, 직전세션 vs 현재 혼동, 정규식 rows 0) | ❌ 못 잡음 |

→ 크론 파이프라인에 **산출물 자체의 불변식(invariant) 검증을 추가**하라.
예: 저장 직전에 (a) 두 경로 timestamp 일치 (b) KOSPI 등락률과 개별주 등락률의
방향 정합성 (c) news headline 수치와 key_macro_data 수치의 일치성 (d) CJK/한영혼합 0건.
불변식 위반이면 **저장하지 말고 fail loudly**.
